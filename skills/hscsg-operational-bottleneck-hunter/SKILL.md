# HSCSG Operational Bottleneck Hunter Skill

## Purpose
Detect, quantify, and eliminate invisible operational bottlenecks through a structured one-question-at-a-time protocol.

## When to Use
- Analyzing workflows to expose hidden constraints
- Building 30/60/90-day elimination roadmaps
- Launching 72-hour bottleneck breaker sprints
- Creating repeatable bottleneck detection method

## Hidden Bottleneck Catalog

### Common Invisible Bottlenecks
1. **Decision Latency** - Delay between information availability and decision
2. **Process Spiderwebs** - Overlapping, undocumented workflows
3. **Skill Gaps** - Missing capabilities causing delays
4. **Legacy Technology** - Outdated systems slowing throughput
5. **Inventory Imbalances** - Over/under stock causing flow issues

### Uncommon but Painful Constraints
1. **Approval Limbo** - Work stuck waiting for sign-offs
2. **Cash-Conversion Lag** - Revenue recognition delays
3. **Mismatched Incentives** - Rewards not aligned with flow
4. **Customer Silence** - Lack of feedback loops
5. **Shadow Processes** - Undocumented workarounds

## Protocol (Single-Question-at-a-Time) — **Alráico Enhanced**

### Phase 1: Define Core Value Stream (Ontológica: qué ES el flujo)
1. Process name? → **Identificar PI topológico del flujo**
2. Start point? → **αʰ₁ (armonía entrada)**
3. End point? → **αʰ₂ (armonía salida)**

### Phase 2: Enumerate Bottlenecks (Teleológica: qué HACE el cuello)
- Present 5 common + 5 uncommon, get confirmation
- **Alráico mapping**: Cada cuello = sobrecarga ΣPᵢ > κ en módulo 𝕮
- **20 límites cognitivos**: Mapear cuellos a límites L1-L20
- Follow-up questions for each confirmed

### Phase 3: Stepwise Exposure Protocol (Axiológica: valorar el costo) — **Triaxial verification**
- **Triaxial verification**: Mental + Simulación + Lab para cada cuello
- a. Boundary Definition - Confirm start/end points (αʰ₁, αʰ₂)
- b. Time-Step Reality - Where to get timing data (Medición Ω)
- c. Idle Gap Ranking - Largest wait vs touch time gap (ΣPᵢ > κ)
- d. Flash Root-Cause Audit - 5 sequential "why" questions (5 porqués Alráicos)
- e. Constraint Confirmation - Would removal increase throughput? (γ-CARMIS test)
- f. Skill Gap Check - If not constraint, skills/resources? (Límite L13: competencia)
- g. Metric Clock-In - Single measurable target (e.g., cut time 30% in 30 days)

### Phase 4: Elimination Plan (30/60/90 Days) — **Alráico Tick Schedule**
- **Tick 1-30 (Fase Lucidez)**: Pilot owners, visual mapping, quick pilots
  - γ-CARMIS: encender lucidez donde CDS > κ
- **Tick 31-60 (Fase Simbiosis)**: SOP refinement, metric expansion
  - Resonancia: αʰ₁·αʰ₂·3.0 > αʰ₁+αʰ₂ entre fases
- **Tick 61-90 (Fase Regeneración)**: Scaling, monitoring, full rollout
  - ECROx: αʰ, s, y, v, XP, k actualizados

### Phase 5: 72-Hour Sprint — **γ-CARMIS Sprint**
- Day 1: Single success metric (Ω target) → **Detectar sobrecarga ΣPᵢ > κ**
- Day 2: Prototype change to test → **γ-CARMIS reconfig** (no parche, reorganiza)
- Day 3: Measured results + locked-in lesson → **Resonancia check** αʰ₁·αʰ₂·3.0

### Anfibio Mode
- **Offline (RAO local)**: Métricas en ZNU, sprints sin presupuesto externo
- **Conectado**: Métricas en USDC vía priceParity, presupuesto disponible
- **γ-CARMIS**: Misma lógica, distinta unidad de cuenta

## Output Format
- Executive Summary
- Catalog (Common + Uncommon with red flags)
- Exposure Protocol (sequential Q&A)
- 30/60/90 Elimination Plan (owners, actions, deadlines)
- 72-Hour Sprint (narrative + checklist)
- Best Practices & Documentation Framework

## Constraints
- One question at a time, wait for answer
- Plain language (10-15 year old comprehension)
- Empathetic, solution-focused, no blame
- Narrative + bullet documentation
- Celebrate quick wins, guard scope creep
